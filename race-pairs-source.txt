# race-pairs-source.txt — the Word Race daily pair pool.
# Design: docs/punctuators-ladder.md §12.3. Build: `python3 build-ladders.py --pairs`.
#
# One `start target` per line. Everything else is computed: the build reads the SHIPPED
# ladderPOJO.js, works out par and the route through the two words' lowest common ancestor, and
# freezes the survivors into racePOJO.js. A `#~` line under each pair is the build's own note —
# it is regenerated on every run, so edit the pair line and leave the note alone.
#
# WHAT MAKES A GOOD PAIR, and why this file is hand-kept:
#   1. Both endpoints are words a player has actually met. This is the whole reason the file
#      exists — no frequency signal in this repo separates `poodle` from `zwieback` (both score
#      zero in SemCor), so a human decides. `--suggest N` does the machine half and appends
#      candidates that clear every filter that CAN be automated; delete the ones you wouldn't ship.
#   2. Every rung on the way DOWN is typeable. The build enforces this (2of12.txt) because the
#      descent is the half the player types; the climb up needs no input, so an odd rung there is
#      free and is not checked.
#   3. Par lands in 4–6. Enforced. Par is a floor, not a target (§12.2 — one rung per move), so
#      it is the best score anyone can post.
#   4. The two words are worth meeting in the middle. The route is the lesson: how far up you must
#      climb is exactly how unrelated two things are, so the fun is in a pair that FEELS close and
#      isn't, or feels distant and isn't.
#
# WORDS DELIBERATELY KEPT OUT, because WordNet's sense is not the player's:
#   dolphin (filed under FISH), peacock (under BUTTERFLY, not bird), seal, bat, drill, crane, fly
#   as a start word — each names two different things and the route would look like a bug.
#
# The order here is not the order shipped — racePOJO.js round-robins the list across trees so the
# daily, which indexes it positionally, changes subject from one day to the next.
